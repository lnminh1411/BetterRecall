# BetterRecall 0.2.0-dev plan

Working plan for v0.2dev (2026-11-11). Batches run in order in one session; tests + package + captures after each.
Decisions taken with the user: redaction before saving; cloud describe sends redacted copy only; Shortcuts gets own
nav page; sequential batches.

## Batch 1: brand, theme, search UI

| Item | Plan |
|---|---|
| Version | `Directory.Build.props` -> `0.2.0-dev` |
| App icon | Clock-history glyph (Segoe Fluent `E81C`) white on cyan (`#4CC2FF`-ish, match screenshot) rounded square; multi-size `.ico` (16-256) for exe, UI window, launcher. Tray: same glyph on transparent, white on dark taskbar, black on light (follow `SystemUsesLightTheme`, refresh on `WM_SETTINGCHANGE`) |
| Theme | `ui.theme` system / light / dark. Applies to main window + search window at once (`RequestedTheme` on roots + title bar button colours) |
| Search layout | Done: card with "Found **query** · 6d ago", `...` button, thumbnail, badge (site or app name with its initial) over the thumbnail |
| 4 sections | Done: one grouped grid, Text matches (keyword hits), Visual matches (vector only), Audio matches (transcripts); Replay matches section appears with batch 4. One row (3 cards) per section, "Show all (N)" expands |
| Filters | Done: app and website dropdowns (single choice each) filled by the `facets` verb for the time range. Site = host read from the Chromium address bar (`privacy.recordSite`), stored in `captures.site` (schema 2) |
| Context menu | Done: `...`, right click or Shift+F10: Copy image / Copy text (kept out of clipboard history), Save as (PNG or text; message says it is not encrypted), Delete (Del), Delete all from app, Delete all from site (count + confirm, fresh token after the dialog) |
| Search history | Done (user request): `privacy.searchHistory` (default on) + `privacy.searchHistoryMax` 100; table `search_history` in the encrypted store; recent searches shown when the box is empty, remove one or clear; off deletes them; time-window purges remove matching searches |
| Always on top | `ui.searchAlwaysOnTop` (default on, today's behaviour): search window topmost or a normal window |
| Start minimized | `startup.minimized` (default on): at logon only the tray icon; off opens Home |
| Light mode contrast | Brushes built in code follow `ui.theme` (theme-aware styles in `App.xaml`); check icon contrast in light captures |
| White box fix | Display affinity never changed on hidden windows: not at window creation, WinEvent hook on SHOW only, no-op when unchanged |
| Shortcuts page | Main-window nav item "Shortcuts": list with press-to-record dialog, conflict check (own keys + `RegisterHotKey` failure), new actions: open timeline, lock, toggle capture, open home |

## Batch 2: capture and storage

| Item | Plan |
|---|---|
| Image formats | `keyframes.format` avif (default), webp, jxl, jpeg. Codec spike first: libavif + encoder (aom) / dav1d decode, libjxl, as native DLLs (download needs go-ahead). Thumbnails and UI receive decodable bytes (agent transcodes when the UI cannot decode) |
| Smart capture | `capture.dirtyMinPercent` default 15 (vs previous stored keyframe). Event triggers still force a capture. Optional "worth capturing" scorer: cheap heuristic first (text-region change, window switch), small model later |
| Storage safeguard | `storage.minFreeGb` 25: below it capture pauses (reason `storage`), banner + tray balloon. `storage.overwrite` on: delete oldest (progressive order) instead of pausing; also when `storage.maxGb` (replaces `keyframes.maxGb`) is exceeded |
| Progressive deletion | `retention.progressiveAfterDays` (start), `retention.progressiveOverDays` (period): thin captures from smallest change (dhash distance / dirty %) to largest, keeping window/app switches; `retention.days` stays the hard limit |
| Export | Export page or Danger-zone section: time window (+ app filter) -> zip of decrypted images + `captures.json` (ts, app, title, text). Warning like replay export; optional zip password (AES) later |

## Batch 3: privacy (OCR + redaction)

| Item | Plan |
|---|---|
| OCR | Optional: `ocr.enabled` (user request 2026-11-11: on-screen OCR, as many languages as possible). Engine choice: Windows.Media.Ocr is built in and offline but reads only languages whose Windows OCR pack is installed (about 25); a multilingual ONNX model (PaddleOCR PP-OCRv5 family, 80+ languages, detection + recognition) on the worker device covers far more. Plan: ONNX engine by default, `ocr.engine` windows / onnx, `ocr.languages` auto. Runs on each kept keyframe; words + boxes; text into `captures.text` + FTS (feeds Text matches); boxes feed redaction |
| Redaction | Before encrypt+store. Detectors, each a setting under `privacy.redact.*`: passwords (UIA password fields' rects + text after password-like labels), payment cards (Luhn), emails, phones, IBAN/national ids, dates of birth (date near birth keywords), names + addresses (small local NER model, multilingual, ONNX on the NSFW device plan). Black boxes on the image; redacted words removed from stored text |
| Video | Replay compositor fills the latest redaction boxes (from the newest OCR pass of that monitor) before encode; boxes live until the next keyframe of that monitor. Documented lag of up to one capture interval |

## Batch 4: extras

| Item | Plan |
|---|---|
| Run as administrator | `startup.elevated`: one UAC prompt registers a logon task with highest privileges (replaces the HKCU `Run` entry), so BetterRecall can see and capture elevated windows; turning it off (one UAC prompt) removes the task. Lands with the new launch flow |
| Unlock without Hello | Done: `security.unlockMethod` hello / password. Argon2id hash in `keys\unlock.bin` (KeyVault Argon2id code), verified in the agent, 5 free tries then 30 s doubling to 900 s, kept across restarts. Works without Hello: the first password may be set without the gate when Hello is not available. Password box + less secure note on the unlock panel; set / change / remove card in Settings > Security (`password` verb) |
| Cloud describe | Done: `ai.enabled` (off) + `ai.provider` / `ai.endpoint` / `ai.model`; key in `keys\ai-key.bin` (DPAPI), never in settings.json or any reply (`ai` verb). Detail pane Describe -> `describe preview` -> dialog (provider, model, endpoint, image) -> `describe send <token>`; audit `describe <provider>` per send. Redaction sits behind `IDescribeRedactor` (pass-through until batch 3; one line in `CoreHost`). API key optional for openai-compatible (local servers). First network use: the no-network guarantee holds only while it is off; turning it on shows a danger confirmation that says the guarantee ends, and a persistent "guarantee off" line shows while on (README, `v1-design.md` 6.1) |
| Cloud chat | Done: Copilot-style chat over the user's own history, built on cloud describe (same `ai.*` provider, DPAPI key held by the agent, `ai.enabled` warning). The model gets one tool, `search_history` (query, from, to, app, site, kind), which runs the agent's own search; Gemini function calling, OpenAI-compatible tools and Claude tool use, streamed. `ai.share` textImages (default) / text / metadata decides what of each hit may go: text is redacted (`BasicTextRedactor`), images go only through a redactor that really redacts, so on this branch the chat says images are unavailable and sends text only. Approval per chat: the first send of captures shows the exact items with previews, items can be unticked, "Allow for this chat"; a new chat asks again. Answers list sources as cards that open the detail view. Placement: Ask toggle in the search window and an Ask page with saved chats (new, rename, delete), encrypted in the store, `ai.chatHistory` off switch. Quota and errors: 429/5xx retried at most twice honouring Retry-After, then a message with the time to try again; billing and quota errors, bad key, unknown model, context too long, offline and timeout each get a plain message; rate-limit headers warn below 10% left; local budget `ai.dailyRequests` / `ai.dailyTokens` warns at 80% and stops at 100%, today's usage shown in Settings > AI. Every request audited `chat <provider>` with the number of captures shared. Mock agent has a scripted chat for UI tests and screenshots (`v1-design.md` 5, 6.2, 8) |
| Replay matches | Done: `replay.searchable` + `replay.sampleSeconds` (5). Samples come from keyframe grabs into a RAM ring, so no video decode; on save they become kind `replay` rows (`replay_frames` table, idempotent migration step). Not in the timeline. Replay matches card "Open replay" opens Replays at that offset: exports, then plays in an in-app player seeked to the offset |

Batch 4 deviations: "Run as administrator" skipped (lands with the new launch flow). Redaction of describe images and replay frames activates when batch 3 merges; until then cloud chat shares redacted text only. Chat approvals live in agent memory, so a restart asks again. "Don't share" lets the model answer without captures rather than ending the turn.
