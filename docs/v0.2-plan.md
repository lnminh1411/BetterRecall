# BetterRecall 0.2.0-dev plan

Working plan for v0.2dev (2026-11-11). Batches run in order in one session; tests + package + captures after each.
Decisions taken with the user: redaction before saving; cloud describe sends redacted copy only; Shortcuts gets own
nav page; sequential batches.

## Batch 2: capture and storage

| Item | Plan |
|---|---|
| Image formats | Done: `keyframes.format` avif (default), webp, jxl, jpeg. Spike on six UI screenshots: AVIF speed 7 at quality-25 about 30% smaller than WebP q75 with lower error, 70-120 ms encode; JXL effort 3 no smaller than WebP (kept as a choice). DLLs built with vcpkg (libavif 1.4.2 + aom + dav1d, libjxl 0.12.0), static CRT, `codecs.LICENSE.txt`. UI gets WebP (`keyframe` verb, thumbs), worker gets `bgra8`, export can convert to JPEG; old WebP/JPEG keyframes unchanged. `--selftest-codec` checks the published build. Plan change (user, 2026-11-12): AVIF goes to the iGPU's AV1 hardware encoder first. Done: `keyframes.encoder` auto / hardware / software (default auto: oneVPL AV1 VDENC on the Intel iGPU, then libaom, then WebP when avif.dll is missing; the RTX 3050 and RX 6600 have no AV1 encode). Reuses `VplAv1Encoder` in a new intra-only constant-QP mode (GOP 1, every frame forced key), one encoder per keyframe size, CPU BGRA to NV12 (BT.709 limited) into a staging texture; `AvifWriter` wraps the packet (ftyp, meta with hdlr/pitm/iloc/iinf av01/ispe/av1C/pixi/colr nclx, clap only if the coded size were larger, mdat; temporal delimiter and padding OBUs dropped). Odd sizes and failures fall back to libaom per frame; 3 failures in a row turn the hardware off. Encoder in use: agent log and the bench page ("Keyframe encoder"). Checked: hardware AVIF decodes with dav1d (libavif) and with Windows WIC (HEIF Image Extension + AV1 Video Extension) although still_picture is 0; the encoder codes the exact picture size (534, 718, 1138 high: no padding). Hardware is 4:2:0 8-bit only: small coloured text loses chroma detail. OCR (batch 3) must read the raw BGRA grab, never the encoded keyframe. Spike 2026-11-12 (`HwAvifSpikeTests`, `BR_HWAVIF_SPIKE`; 5 README UI screenshots plus code / text page / coloured-UI renders, not live screen grabs), hardware QP picked to match libaom's PSNR on text blocks: hardware 4 ms wall and under 10 ms CPU per 1280 px frame vs libaom 75-120 ms wall and 95-190 ms CPU. Size at default quality 75: UI screenshots 25-27 KiB hardware vs 12-21 libaom vs 15-32 WebP (hardware 1.25-1.35x libaom, about WebP size); code 58 vs 20 vs 64; text page 78 vs 21 vs 53; coloured UI 105 vs 14 vs 77 (2.8-7.8x libaom). libaom wins on text through its screen-content tools (palette, intra block copy), which the VDENC hardware lacks. Chroma error on coloured pixels is 5-40% higher for the hardware. QP map kept: q75 -> QP 120, 3 QP per quality point (q60 -> 165, q90 -> 75). Open: whether auto should stay hardware-first given the storage cost on text-heavy screens |
| Smart capture | Done: `capture.dirtyMinPercent` default 15, scored against the previous stored keyframe (`ChangeMap`: 32 px tiles, text-like tiles weigh 5x). Window/app switch and first frame always kept; event triggers need 0.5; `capture.dhashThreshold` 0 = off. Score and switch flag stored per row. Model scorer: later |
| Storage safeguard | Done: `storage.minFreeGb` 25 (free disk + free DB pages), `storage.maxGb` 20 (live store + keyframes; `keyframes.maxGb` moved on load), `storage.overwrite` (default off). Pause reason `storage`: tray balloon once + main-window banner with a "Storage settings" button; overwrite deletes in progressive order (`IStore.DeleteForSpace`), pauses only when nothing is left. Resume needs a small margin |
| Progressive deletion | Done: `retention.progressiveAfterDays` 7 (0 = off), `retention.progressiveOverDays` 30. A day keeps ceil(n x (1-p)) rows, n = its count when thinning began (`thin_days`); smallest `change_pct` first, switches and audio kept; pre-0.2 rows scored from dHash + app/title change. New month files use incremental vacuum |
| Export | Done: Danger zone card: from/to, optional app, "convert to JPEG"; dry-run count, "not encrypted" warning, save picker, "Show in folder". Verb `export <json>` -> zip (`images/` + `captures.json` with ts, app, title, site, text, file). Zip password: later |

## Batch 3: privacy (OCR + redaction)

| Item | Plan |
|---|---|
| OCR | Optional: `ocr.enabled` (user request 2026-11-11: on-screen OCR, as many languages as possible). Engine choice: Windows.Media.Ocr is built in and offline but reads only languages whose Windows OCR pack is installed (about 25); a multilingual ONNX model (PaddleOCR PP-OCRv5 family, 80+ languages, detection + recognition) on the worker device covers far more. Plan: ONNX engine by default, `ocr.engine` windows / onnx, `ocr.languages` auto. Runs on each kept keyframe; words + boxes; text into `captures.text` + FTS (feeds Text matches); boxes feed redaction |
| Redaction | Before encrypt+store. Detectors, each a setting under `privacy.redact.*`: passwords (UIA password fields' rects + text after password-like labels), payment cards (Luhn), emails, phones, IBAN/national ids, dates of birth (date near birth keywords), names + addresses (small local NER model, multilingual, ONNX on the NSFW device plan). Black boxes on the image; redacted words removed from stored text |
| Video | Replay compositor fills the latest redaction boxes (from the newest OCR pass of that monitor) before encode; boxes live until the next keyframe of that monitor. Documented lag of up to one capture interval |

## Batch 4: extras

| Item | Plan |
|---|---|
| Run as administrator | `startup.elevated`: one UAC prompt registers a logon task with highest privileges (replaces the HKCU `Run` entry), so BetterRecall can see and capture elevated windows; turning it off (one UAC prompt) removes the task. Lands with the new launch flow |
| Unlock without Hello | `security.unlockMethod` hello / password. Password: Argon2id hash in `<data>`, verified in agent, rate-limited; works when Hello is not set up. Less secure note in UI |
| Cloud describe | Settings `ai.provider` (gemini / openai-compatible / claude), `ai.endpoint`, `ai.model`; key stored DPAPI-encrypted in its own file, never in settings.json. Off by default. Detail pane "Describe" -> confirmation (provider, model, redacted image preview) -> agent sends redacted image, shows text. Audit log entry per send |
| Replay matches | On replay save: sample a frame every few seconds, redact, embed, store as capture kind `replay` (replay id + offset). Section opens the replay at that offset |
