# BetterRecall 0.2.0-dev plan

Working plan for v0.2dev (2026-11-11). Batches run in order in one session; tests + package + captures after each.
Decisions taken with the user: redaction before saving; cloud describe sends redacted copy only; Shortcuts gets own
nav page; sequential batches.

## Batch 2: capture and storage

| Item | Plan |
|---|---|
| Image formats | Done: `keyframes.format` avif (default), webp, jxl, jpeg. Spike on six UI screenshots: AVIF speed 7 at quality-25 about 30% smaller than WebP q75 with lower error, 70-120 ms encode; JXL effort 3 no smaller than WebP (kept as a choice). DLLs built with vcpkg (libavif 1.4.2 + aom + dav1d, libjxl 0.12.0), static CRT, `codecs.LICENSE.txt`. UI gets WebP (`keyframe` verb, thumbs), worker gets `bgra8`, export can convert to JPEG; old WebP/JPEG keyframes unchanged. `--selftest-codec` checks the published build. Plan change (user, 2026-11-12): an iGPU AV1 (oneVPL VDENC) path was built and measured, then dropped by the user: 4 ms per frame but 1.3x libaom size on UI screens and 2.8-7.8x on text-heavy screens (no palette or intra block copy). AVIF stays on the CPU (libaom, one thread, below-normal EcoQoS thread) under a hard CPU budget (user): keyframe encoding may use under 1 % CPU on average over 60 s and at most 1.5 % in any 10 s, as Task Manager counts it (share of all logical processors; 20 on the dev PC, Core Ultra 7 265K), during normal capture with default settings. `EncodeGovernor` measures each encode's thread CPU and plans against 80 % of the 10 s cap and 90 % of the 60 s cap; the fuller window picks the level (under half: Normal libaom speed 7, under three quarters: Fast speed 8, else Reduced speed 9 at 75 % size and quality - 10), falling to a cheaper level when the chosen one does not fit; when none fits, kept frames wait (queue of 6, oldest first, the newest never dropped); a full queue or a frame waiting over 30 s goes to WebP when that fits, else is dropped. Event-triggered bursts count like any frame. Level shown in the agent log, the tray status ("keyframes: CPU budget, ...") and the bench page. Preset spike (`KeyframeCostSpikeTests`, `BR_KF_SPIKE`; 5 README screenshots plus code / text page / coloured-UI renders, one thread, quality 75): speed 7 127 ms CPU 18.5 KiB, speed 8 60 ms 27.6 KiB, speed 9 = 10 20 ms 40 KiB (soft text), WebP 31 ms 40 KiB, JPEG 6 ms 79 KiB; tune-content screen changed nothing at 7-8 and tripled the cost at 9; speed 6 costs 1.8x speed 7 for 3 % less. Real run (`--selftest-keyframe-budget 10`, AOT build, 3 monitors, normal use, 2026-11-12): 203 frames kept of 882 grabs, all at Normal (run made before the load-based level choice; its worst 10 s, 73 % of the target, would now encode a few frames at Fast), 156 ms CPU / 160 ms wall per frame; encode CPU average 0.26 %, worst 10 s 0.88 %, worst 60 s 0.45 %; at matched text sharpness AVIF 16.9 KiB, WebP 34.1 KiB (2.0x), JPEG 108.5 KiB (6.4x). AvifWriter (HEIF still from raw AV1 OBUs) stays for a later encoder that outputs OBUs. OCR (batch 3) must read the raw BGRA grab, never the encoded keyframe |
| Smart capture | Done: `capture.dirtyMinPercent` default 15, scored against the previous stored keyframe (`ChangeMap`: 32 px tiles, text-like tiles weigh 5x). Window/app switch and first frame always kept; event triggers need 0.5; `capture.dhashThreshold` 0 = off. Score and switch flag stored per row. Model scorer: later |
| Storage safeguard | Done: `storage.minFreeGb` 25 (free disk + free DB pages), `storage.maxGb` 20 (live store + keyframes; `keyframes.maxGb` moved on load), `storage.overwrite` (default off). Pause reason `storage`: tray balloon once + main-window banner with a "Storage settings" button; overwrite deletes in progressive order (`IStore.DeleteForSpace`), pauses only when nothing is left. Resume needs a small margin |
| Progressive deletion | Done: `retention.progressiveAfterDays` 7 (0 = off), `retention.progressiveOverDays` 30. A day keeps ceil(n x (1-p)) rows, n = its count when thinning began (`thin_days`); smallest `change_pct` first, switches and audio kept; pre-0.2 rows scored from dHash + app/title change. New month files use incremental vacuum |
| Export | Done: Danger zone card: from/to, optional app, "convert to JPEG"; dry-run count, "not encrypted" warning, save picker, "Show in folder". Verb `export <json>` -> zip (`images/` + `captures.json` with ts, app, title, site, text, file). Zip password: later |

## Batch 3: privacy (OCR + redaction)

| Item | Plan |
|---|---|
| OCR | Optional: `ocr.enabled` (user request 2026-11-11: on-screen OCR, as many languages as possible). Engine choice: Windows.Media.Ocr is built in and offline but reads only languages whose Windows OCR pack is installed (about 25); a multilingual ONNX model (PaddleOCR PP-OCRv5 family, 80+ languages, detection + recognition) on the worker device covers far more. Plan: ONNX engine by default, `ocr.engine` windows / onnx, `ocr.languages` auto. Runs on each kept keyframe; words + boxes; text into `captures.text` + FTS (feeds Text matches); boxes feed redaction |
| Redaction | Before encrypt+store. Detectors, each a setting under `privacy.redact.*`: passwords (UIA password fields' rects + text after password-like labels), payment cards (Luhn), emails, phones, IBAN/national ids, dates of birth (date near birth keywords), names + addresses (small local NER model, multilingual, ONNX on the NSFW device plan). Black boxes on the image; redacted words removed from stored text |
| Video | Replay compositor fills the latest redaction boxes (from the newest OCR pass of that monitor) before encode; boxes live until the next keyframe of that monitor. Documented lag of up to one capture interval |

## Batch 4: extras

| Item | Plan |
|---|---|
| Run as administrator | `startup.elevated`: one UAC prompt registers a logon task with highest privileges (replaces the HKCU `Run` entry), so BetterRecall can see and capture elevated windows; turning it off (one UAC prompt) removes the task. Lands with the new launch flow |
| Unlock without Hello | Done: `security.unlockMethod` hello / password. Argon2id hash in `keys\unlock.bin` (KeyVault Argon2id code), verified in the agent, 5 free tries then 30 s doubling to 900 s, kept across restarts. Works without Hello: the first password may be set without the gate when Hello is not available. Password box + less secure note on the unlock panel; set / change / remove card in Settings > Security (`password` verb) |
| Cloud describe | Done: `ai.enabled` (off) + `ai.provider` / `ai.endpoint` / `ai.model`; key in `keys\ai-key.bin` (DPAPI), never in settings.json or any reply (`ai` verb). Detail pane Describe -> `describe preview` -> dialog (provider, model, endpoint, image) -> `describe send <token>`; audit `describe <provider>` per send. Redaction sits behind `IDescribeRedactor` (pass-through until batch 3; one line in `CoreHost`). API key optional for openai-compatible (local servers). First network use: the no-network guarantee holds only while it is off; turning it on shows a danger confirmation that says the guarantee ends, and a persistent "guarantee off" line shows while on (README, `v1-design.md` 6.1) |
| Replay matches | Done: `replay.searchable` + `replay.sampleSeconds` (5). Samples come from keyframe grabs into a RAM ring, so no video decode; on save they become kind `replay` rows (`replay_frames` table, idempotent migration step). Not in the timeline. Replay matches card "Open replay" opens Replays at that offset: exports, then plays in an in-app player seeked to the offset |

Batch 4 deviations: "Run as administrator" skipped (lands with the new launch flow). Redaction of describe images and replay frames activates when batch 3 merges.
