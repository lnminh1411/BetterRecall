# BetterRecall 0.4.0-dev plan

Working plan for 0.4.0-dev, written 2026-11-27 from `main` at `b36507f`. The work runs in seven checkpoints, in order. Each checkpoint ends with its tests and clippy green, a `--no-ff` merge to `main` and a push to GitHub.

Decisions taken with the user:
- **Branding:** BetterRecall contributors is the publisher only. The product stays BetterRecall, so data folder, registry keys, mutex and pipe names don't change and no migration is needed.
- **Installer model download:** the new button stops the model download only. The install finishes and partial files are kept, so the Models page resumes them.
- **Website:** the github.com/lnminh1411/BetterRecall website is handled in another session. This plan only links to it.
- **Sweep numbers:** the two full sweeps are numbered 8 and 9; sweep 7 already ran (`b36507f`).
- **UI rewrite (added 2026-11-28):** the UI moves from WinUI 3 to GPUI-CE (`gpui-ce` 0.3.0) with `gpui_ce_components` 0.3.0, mainly for performance. It is a rewrite, not a restyle: styling, animation and design stay as they are in WinUI 3. A new "Limited Motion" option turns animation off.
- **Platforms:** the app stays Windows only. Linux is planned for later, so platform code is kept apart. macOS is not planned.
- **Rewrite decisions (2026-11-28):**
  - **Replay player:** the in-app player decodes clips itself (Media Foundation into GPUI frames).
  - **Screen readers:** stay off until GPUI-CE supports them properly. The AccessKit adapter is not enabled in 0.4. Controls still get names in code, so turning it on later is a switch. The README lists this as a known gap against 0.3.
  - **Licence (decided 2026-11-28):** everything is AGPL-3.0-only from now on, the UI included. The MIT split (WinUI UI, C# Contracts, UI tests, `br-contracts`) ends in checkpoint 2. GPUI-CE, `gpui_ce_components` and `native-theme` are Apache-2.0 or MIT, which AGPL-3.0 code may use.
  - **No real GPU:** Windows Sandbox and remote sessions run on vGPU, so no software-render path is planned.
  - **Checkpoint 2 answers (2026-11-28):** Muse Code is Meta's AI coding harness. Buy Me A Coffee, GitHub and other link targets are placeholders until the user sends them (one constant table, `TODO(links)`). Artwork stays in the current style; the banner loses its motto, and the demo images (mock thumbnails, README shots, banner) are real rendered pages instead of drawn bars. The copyright holder becomes BetterRecall contributors. MCP stays text and structured output, with no images. Claude advances through the checkpoints on its own and stops after checkpoint 5 for the user's review (checkpoints 6 and 7 wait for that), with Gemini `gemini-4-neon-medium` for bulk code.
  - **Theme:** colours and fonts come from `native-theme`. The stack stays on GPUI-CE with a connector of our own; upstream `native-theme-gpui` targets `gpui-pre` and longbridge `gpui-component` instead (see checkpoint 4a).

## Checkpoint 4a: UI rewrite on GPUI-CE

### Feasibility research (2026-11-28)

Two read-only passes: an inventory of every WinUI 3 and Win32 capability the UI uses today (`src\BetterRecall.UI`), and a web check of `gpui-ce` and `gpui_ce_components` (source on GitHub, docs.rs, crates.io; nothing built or run). Items marked "unverified" are reasoned from source, not tested.

| What the UI uses today | GPUI-CE 0.3.0 | Plan |
|---|---|---|
| Two windows created once and kept warm; show and hide without destroying them | yes: `WindowOptions.show`, `Window::set_visible` | as is |
| Launcher: borderless with resize border, hidden from Alt-Tab, always on top (re-read on every show), hide on deactivate except while a menu or picker is open | partial: `WindowKind::PopUp` sets topmost only at creation | `SetWindowPos(HWND_TOPMOST)` and `WS_EX_TOOLWINDOW` on the raw HWND (`HasWindowHandle` is implemented) |
| Main window custom title bar with themed caption buttons, 640x480 minimum size | yes: transparent title bar, `title_bar` component, `window_min_size` | as is |

| `SetWindowDisplayAffinity` on every window of the process, including system popups | yes through the HWND; simpler, since GPUI draws menus, tooltips and dialogs inside the window | keep the "never change affinity on a hidden window" rule |

## Checkpoint 4b: new features and additions

| Item | Plan |
|---|---|
| MCP client page | New page "MCP" in the settings shell, on `br-mcp-clients` from checkpoint 2. It shows the server state (`mcp.enabled`, agent pipe up, relay path `<data>\app\bin\betterrecall-mcp.exe`) and one row per client: detected or not, configured or not, and Add, Remove and Copy config buttons. |
| Installer Stop download | While the Progress page is in `Step::DownloadingModels` (install and Modify), the button reads "Stop download". It sets a models-only stop flag. `download_models_set` ends like a cancel (within a quarter second), the `.part` files stay, and the run goes on: install finishes with exit 0 and writes the effective model mode (Install later when nothing complete arrived). The Finish page says the models were not downloaded and that the Models page resumes them. Before the model step, Cancel keeps today's meaning (abort, exit 8). Silent runs get no button. Tests: a stop mid-download leaves the app installed, `.part` files present, `ModelMode` right, exit 0. |
| Signing preparation | Authenticode signing arrives with 1.0.0; 0.4 only prepares it, no certificate. (1) `build_installer.py --sign` hook: signs every PE in the release layout with `signtool` (SHA-256, RFC 3161 timestamp) before `integrity.json` is generated, since signing changes the file bytes the manifest hashes, then signs the installer last. The certificate is picked by thumbprint or by an Azure Trusted Signing profile from the environment, and nothing secret goes in the repo. (2) The installer payload trailer sits at the end of the exe, where Authenticode appends its certificate table. The trailer reader must find the payload through the PE security directory, or the payload must move into a resource. Spike both and pick one. (3) Test the whole chain with a self-signed test certificate made inside Windows Sandbox only, never in the host certificate store. (4) `docs\release-signing.md`: certificate route (OV, EV or Azure Trusted Signing), SmartScreen reputation, the order of steps, and how it relates to the release key (`docs\key-trust.md`). |
| About and links | New "About" page in the settings shell: version, publisher BetterRecall contributors, links to GitHub, github.com/lnminh1411/BetterRecall, Hugging Face models, licences, "Report a problem" (below) and "Support development" (Buy Me A Coffee). Links open in the default browser through the shell; the app itself still makes no request, so the no-network guarantee holds. Donation prompt: in About and the README, plus one dismissible Home card after 14 days of use, shown once and never again after "Not now". |
| Tutorials and first start | First-start flow after consent: welcome, what is captured and what is skipped, privacy controls (pause, exclusions, private windows, lock), hotkeys, a search demo, then setup options (capture on or off, replay, speech, autostart, unlock method, cloud AI stays off). Every step can be skipped, and Help reopens the flow. WinUI `TeachingTip` on the first visit to Search, Timeline, Replays and MCP. A user guide `docs\user-guide.md`, linked from Help, the README and the website. |
| VirusTotal procedure | `docs\release-procedure.md` plus `Scripts\virustotal_check.py`. The script first looks up the SHA-256 of the installer and every PE in the layout; uploads only with `--upload` and an API key from the environment, since an upload makes the file public on VirusTotal. A release goes out only with no detections from the major engines, or with each detection documented and reported to the vendor as a false positive. Run by the user at release time only, never by tests. |
| Feedback via GitHub Issues | `.github\ISSUE_TEMPLATE\` with `bug_report.yml` (version, Windows build, steps, logs pasted by the user), `feature_request.yml` and `config.yml` (security reports go to private advisories). Adds `SECURITY.md`, `CONTRIBUTING.md`, labels and a triage note in the release procedure. In the app, "Report a problem" opens a new issue prefilled with the version and Windows build only. "Copy diagnostics" copies a short text (versions, settings that are not secret, worker device, last errors without titles or paths) for the user to review and paste. |
